# CTF 平台 RBAC 权限架构设计文档

## 一、角色总览

| 角色 | 标识 | 作用域 | 说明 |
|------|------|--------|------|
| 超级管理员 | `root` | 全局 | 唯一，系统初始化时创建，不可删除 |
| 站点管理员 | `site_admin` | 全局 | 由 root 授权，可管理平台全局内容 |
| 赛事管理员 | `contest_admin` | 赛事级 | 由 site_admin 在创建赛事时指定，权限限定在对应赛事内 |
| 普通用户 | `user` | 个人 | 默认注册角色，可参赛、练习、组队 |

权限继承链：`root → site_admin → contest_admin → user`

---

## 二、各角色权限明细

### 2.1 root（超级管理员）

- 修改站点全局配置（等价于管理 .env 环境变量）
- 将任意用户的全局角色升降为 `site_admin` / `user`
- 拥有 `site_admin` 的全部权限
- 查看全平台审计日志
- 强制关闭 / 重置任意赛事
- 管理第三方服务集成（邮件、OSS、Docker 等）

> root 账户唯一且不参与积分排名，不可被其他角色修改。

---

### 2.2 site_admin（站点管理员）

**内容管理：**
- 发布 / 编辑 / 下线平台公共题库题目（`scope = 'platform'`）
- 管理题目附件、Docker 镜像
- 发布 / 编辑平台公告与站内消息

**赛事管理：**
- 创建赛事，并在表单中指定一个或多个 `contest_admin`
- 编辑任意赛事的元信息
- 强制开启 / 暂停 / 结束任意赛事
- 审核赛事报名（当赛事开启报名审核时）

**用户管理：**
- 查看所有用户信息
- 封禁 / 解封用户账户
- 不可修改用户的全局 role（该权限仅 root 拥有）

---

### 2.3 contest_admin（赛事管理员）

**作用域限制：** 所有权限仅在被指定的赛事内有效，且仅在赛事结束前可操作。

**赛事内容管理：**
- 向本赛事添加 / 移除题目
  - 可从平台公共题库引用（`contest_challenges` 关联）
  - 可创建本赛事专属题目（`problems.scope = 'contest'`）
- 编辑本赛事的元信息（标题、描述、封面、时间）
- 管理本赛事的题目分值覆盖（`contest_challenges.score_override`）

**参赛者管理：**
- 查看本赛事报名列表
- 审核报名申请（`contest_participants.status`）
- 取消参赛者资格

**赛事监控：**
- 查看本赛事实时排行榜
- 查看本赛事提交记录（含 IP）

> contest_admin 不具备平台公共题库的管理权限，也不能跨赛事操作。

---

### 2.4 user（普通用户）

- 浏览平台公共题库，提交 flag
- 报名参加赛事（个人或以战队形式）
- 创建战队、邀请成员、担任队长
- 管理个人资料与账户安全
- 查看个人提交历史与排名

---

## 三、数据库设计

### 3.1 全局角色：`users.role`
```sql
-- 全局角色仅三个值，contest_admin 不存这里
CONSTRAINT role_valid CHECK (role IN ('root', 'site_admin', 'user'))
```

### 3.2 赛事级角色：`contest_admins` 表
```sql
CREATE TABLE contest_admins (
    id          CHAR(36) PRIMARY KEY,
    contest_id  CHAR(36) NOT NULL,
    user_id     CHAR(36) NOT NULL,
    role        VARCHAR(16) NOT NULL DEFAULT 'admin',
    -- 'admin'   : 可增删题目、编辑赛事元信息、管理参赛者
    -- 'observer': 只读，用于监考、裁判观察场景
    granted_by  CHAR(36),       -- 授权人（site_admin 或 root）
    granted_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    UNIQUE KEY uniq_contest_admin (contest_id, user_id),
    FOREIGN KEY (contest_id) REFERENCES contests(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id)    REFERENCES users(id)    ON DELETE CASCADE,
    FOREIGN KEY (granted_by) REFERENCES users(id)    ON DELETE SET NULL
);
```

### 3.3 赛事归属：`contests.created_by`
```sql
ALTER TABLE contests
    ADD COLUMN created_by CHAR(36),
    ADD FOREIGN KEY fk_contests_created_by (created_by)
        REFERENCES users(id) ON DELETE SET NULL;
```

### 3.4 题目归属与作用域：`problems` 扩展
```sql
ALTER TABLE problems
    ADD COLUMN created_by  CHAR(36),
    ADD COLUMN scope       VARCHAR(16) NOT NULL DEFAULT 'platform',
    -- 'platform' : 平台公共题库，site_admin 管理
    -- 'contest'  : 赛事专属题目，赛事结束后自动不可见
    ADD COLUMN contest_id  CHAR(36),
    ADD CONSTRAINT scope_valid CHECK (scope IN ('platform', 'contest')),
    ADD FOREIGN KEY fk_problems_created_by (created_by)
        REFERENCES users(id) ON DELETE SET NULL,
    ADD FOREIGN KEY fk_problems_contest_id (contest_id)
        REFERENCES contests(id) ON DELETE CASCADE;
```

### 3.5 报名状态：`contest_participants.status`
```sql
ALTER TABLE contest_participants
    ADD COLUMN status VARCHAR(16) NOT NULL DEFAULT 'approved',
    ADD CONSTRAINT status_valid CHECK (status IN ('pending', 'approved', 'rejected'));
```

### 3.6 角色变更审计：`role_change_logs` 表
```sql
CREATE TABLE role_change_logs (
    id           CHAR(36) PRIMARY KEY,
    operator_id  CHAR(36),           -- 操作人（root）
    target_id    CHAR(36) NOT NULL,  -- 被操作用户
    old_role     VARCHAR(16) NOT NULL,
    new_role     VARCHAR(16) NOT NULL,
    reason       VARCHAR(255),
    created_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (operator_id) REFERENCES users(id) ON DELETE SET NULL,
    FOREIGN KEY (target_id)   REFERENCES users(id) ON DELETE CASCADE
);
```

## 四、鉴权逻辑速查

| 操作 | 鉴权条件 |
|------|----------|
| 修改站点配置 | `role = 'root'` |
| 升降用户全局角色 | `role = 'root'` |
| 发布公告 / 管理公共题库 | `role IN ('root', 'site_admin')` |
| 创建赛事 | `role IN ('root', 'site_admin')` |
| 指定赛事管理员 | `role IN ('root', 'site_admin')` |
| 编辑赛事元信息 | `role IN ('root', 'site_admin')` 或 `contest_admins` 中有 `admin` 记录 |
| 赛事内发题（赛事结束前） | `contest_admins` 中有 `admin` 记录 且 `NOW() < contests.end_time` |
| 审核报名 | `contest_admins` 中有记录 或 `role IN ('root', 'site_admin')` |
| 查看赛事提交记录 | `contest_admins` 中有记录 或 `role IN ('root', 'site_admin')` |
| 参赛 / 提交 flag | 已登录用户（任意 role） |
| 创建 / 管理战队 | 已登录用户（任意 role） |

## 五、业务边界说明

**题目可见性规则：**
- `scope = 'platform'`：按 `visible_from / visible_to` 控制，与赛事无关
- `scope = 'contest'`：以 `contests.end_time` 为准，赛事结束后题目自动归档，不再对普通用户可见

**赛事管理员生命周期：**
- 赛事创建时由 `site_admin` 在表单中指定
- 赛事结束后 `contest_admin` 权限自动失效（后端以 `NOW() < end_time` 判断）
- `site_admin` 可随时撤销某用户的 `contest_admin` 身份（删除 `contest_admins` 对应行）

**战队与赛事的关系：**
- 战队是平台全局概念，不隶属于单场赛事
- 参赛时以战队身份报名，记录在 `contest_participants.team_id`
- 战队积分与赛事积分独立维护，分别由 `teams.score` 和 `contest_scores` 管理

## 六、扩展方向

| 方向 | 说明 |
|------|------|
| 邀请码报名 | `contests` 表增加 `invite_code` 字段，限制私有赛事访问 |
| 题目审核流 | `problems` 增加 `status`（draft / review / published），site_admin 审核后发布 |
| OAuth 登录后角色同步 | 外部登录用户默认 `user`，需手动由 root / site_admin 提权 |
| 赛事可见性分级 | 增加 `contests.visibility`（public / invite_only / private）控制赛事入口 |
