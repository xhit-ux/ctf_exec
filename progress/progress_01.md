# CTF 平台项目进度总结与规划 v3.0

**文档更新时间**: 2026-03-17  
**项目名称**: CTF Exec Platform  
**定位**: 真实可部署、可长期维护的 CTF 平台

---

## 1. 项目当前状态

### 1.1 已完成（核心可用）

1. 后端基础架构完成：Gin + 分层架构（Handler/Service/Repository）
2. 认证与用户基础能力完成：注册、登录、JWT、个人资料维护
3. 题目与提交基础链路完成：题目列表/详情、Flag 提交、提交记录
4. 团队能力完成：创建、加入、退出、解散、队长管理成员
5. Redis 集成完成：排行榜缓存与提交限流
6. 数据库主结构完成：用户、团队、题目、提交、赛事相关核心表均已落地

### 1.2 进行中（高优先）

1. 管理端能力（题目/赛事/用户）尚未完整实现
2. 赛事业务 API（CRUD、报名、赛事题目隔离）尚未完整实现
3. 权限体系需要升级为 `root/admin/user` 的统一 RBAC

### 1.3 待完成（中优先）

1. 错误码和统一错误处理中间件
2. 结构化日志（zap/logrus）
3. API 文档（Swagger/OpenAPI）
4. 测试覆盖率提升（优先 Service 层）

## 2. 数据库与权限改造结论

基于当前 `db/final_01.sql` 与后端实现，角色改造结论如下：

1. 现在改角色分层来得及，且应优先执行
2. 授权角色采用：`root/admin/user`
3. 认证来源采用：`auth_provider`（`local/github/...`），与授权角色分离
4. 角色变更必须有审计记录（`user_activity_logs`）

详细任务见：`progress/角色划分.md`

## 4. 风险与控制

1. 风险：角色变更后旧 JWT 仍有效
控制：缩短 JWT TTL，角色变更后强制重新登录（后续可加黑名单）

2. 风险：权限判断散落在 Handler，容易遗漏
控制：统一 RBAC 中间件 + 路由组集中控制

3. 风险：文档与 SQL/代码不一致
控制：每次 schema 变更同时更新 `progress_01.md` 与 `db/final_01.sql`
