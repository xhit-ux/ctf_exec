## 2. 数据库与权限改造结论

基于当前 `db/final_01.sql` 与后端实现，角色改造结论如下：

1. 现在改角色分层来得及，且应优先执行
2. 授权角色采用：`root/admin/user`
3. 认证来源采用：`auth_provider`（`local/github/...`），与授权角色分离
4. 角色变更必须有审计记录（`user_activity_logs`）

详细任务见：`progress/角色划分.md`

## 4. 风险与控制

1. 风险：角色变更后旧 JWT 仍有效
控制：缩短 JWT TTL，角色变更后强制重新登录（后续可加黑名单）

2. 风险：权限判断散落在 Handler，容易遗漏
控制：统一 RBAC 中间件 + 路由组集中控制

3. 风险：文档与 SQL/代码不一致
控制：每次 schema 变更同时更新 `progress_01.md` 与 `db/final_01.sql`
